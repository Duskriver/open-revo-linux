# OpenRevo for Linux — 0.9.3-linux.2 完整包预览

基于 [faintonce/open-revo](https://github.com/faintonce/open-revo)，保留上游来源与 GPL-3.0-or-later 许可，由 [Duskriver](https://github.com/Duskriver) 维护。

`0.9.3-linux.2` 将应用和驱动合并为一个安装包。完整包已在当前唯一使用的本机安装并验证，以下实机记录仅对应这台机器。

## 变化

- Linux 唯一前端与 Rust 入口，类型化 IPC，宿主不再重复实现核心硬件逻辑。
- 保留监控、主题、诊断、自启动、系统档位、背光及内核公开的限充接口。
- GM5HG7A 驱动改用内核模式/功耗/强冷事务，关闭原始寄存器写入口；应用与驱动要求协议版本匹配。
- GUI 与 DKMS 驱动源码合入一个完整 `.deb`，APT 安装所需依赖，并自动替换旧的拆分驱动包。
- 正常匹配的内核与机型安装后自动构建、启用模块；升级不强卸载活跃模块，需要重启时明确提示。
- 分发只有一个 `OpenRevo_<version>_amd64.deb`，另附对应源码及 SHA-256 校验。
- 实机修正固件提交后消费静音请求标志所导致的误报回滚，其他稳定字段及传输失败继续严格校验。

## 安装和升级

联网使用 APT 安装完整包，无需另装驱动 Debian 包：

```sh
sudo apt install ./OpenRevo_0.9.3-linux.2_amd64.deb
```

APT 安装 GUI 运行库、DKMS 和构建依赖；非标准内核仍需提供匹配 headers。Secure Boot 需要完成系统要求的签名和 MOK 登记。已安装的拆分驱动包由包关系替换，手工安装的旧模块仍需按提示备份并处理冲突。升级不会强制卸载忙碌模块；若提示重启，新驱动在重启后启用。旧或不兼容模块保持只读监测。GUI 以普通用户运行，详见 [安装与升级说明](linux-port.md#完整-debian-包安装与升级)。

等待 headers、MOK、重启或机型不受支持时，安装可完成并明确记录 OEM 未就绪，标准系统监控仍可使用；实际驱动编译失败和手工模块冲突会作为配置错误报告。

## 验证边界

完整包本地构建已通过 `pnpm check`（34 项 Python 测试、41 项 Rust 测试和 TypeScript 检查）及包内容校验。隔离 dpkg 数据库验证了旧双包升级、配置保留、卸载与清除；驱动加载、权限、Secure Boot 拒绝和容器边界使用模拟命令测试。包内应用窗口回归 10 项通过，2 项真实硬件写回默认跳过；包内驱动源码针对 Linux `7.0.0-38-generic` 编译通过，未加载。

2026-11-01 本机实际通过 APT 安装完整包：`open-revo` 升级为 `0.9.3-linux.2`，旧独立驱动包卸载，DKMS 为当前内核编译、签名并安装同版本模块，未额外升级内核。加载中模块与新模块的源码标识一致，因此无需重载或重启；安装程序验证了当前用户的设备读写权限，结果为 `ready`。

安装后的 `/usr/bin/open-revo` 窗口回归 10 项通过，2 项系统/平台档位写回跳过。5 秒强冷实测为 5085/5210 RPM，释放后强冷关闭，原有狂暴模式、90/90/100 W 出厂功耗和故障标志均保持正常。已通过系统桌面入口重新打开新版应用，保留本次回退文件和验证记录。

下述实机结果来自 2026-11-01 合并完整安装包之前的应用与事务驱动，不构成 `0.9.3-linux.2` 安装、升级流程的验证报告。

- 新驱动只匹配 MECHREVO / GM5HG7A / BIOS N.1.09MRO19。
- 2026-11-01 已安装配套新应用与 DKMS 驱动。新事务驱动连续 5 次办公模式验证通过，5 秒强冷读数为 5183/5135 RPM，释放后恢复且无故障；旧模块、配置及应用文件保留回退备份。
- 接电下均衡、狂暴和 35/35/70 W 自定义功耗写入/读回通过，结束后恢复测试前均衡模式；系统安装后的原生窗口回归 10 项通过，2 项系统/平台档位真实写回按默认策略跳过。
- 接电功耗效果、自定义曲线带载散热、其他 BIOS/机型尚未完成验证。
- RGB、水冷、GPU MUX 和 Linux 插件仍待实现。
- 系统性能档位与 OEM EC 模式不是同一个接口。

完整功能、构建和验证流程见 [Linux 文档](linux-port.md)，阶段证据见 [重构记录](linux-refactor.md)。
