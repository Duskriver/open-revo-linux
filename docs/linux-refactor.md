# Linux-only 重构记录

目标：以 Linux 为唯一支持平台，保留现有 Linux 功能、界面操作及硬件策略语义，分阶段整理代码、驱动协议和发布流程。继续使用 Rust、Tauri、React；不扩展未验证机型，模块部署和实机调节须另行明确确认。

## 验收边界

- 保留系统监控、系统/平台性能档位、OEM 模式、风扇强冷、CPU 功耗、曲线草稿/应用/恢复、限充、背光、自启动、主题和诊断。
- 未实现的 RGB、水冷、GPU 切换和插件仍明确显示支持状态。
- 模式/功耗成功应用后的驻留行为不变；风扇原有租约、退出和休眠恢复语义不变。
- 普通用户运行 GUI；寄存器/协议留在 HAL 与规范字典，未知数据保持未知。
- 原生窗口回归默认不写真实硬件。显式设置 `OPENREVO_TEST_HARDWARE_WRITES=1` 才执行当前档位写回检查。
- 未经实机验证的功能继续保留原验证等级；软件测试通过不能证明带载硬件效果。

## 命名场景与 CLI（2026-11-01）

> 历史实现记录：该方案于 2026-11-02 按新架构蓝图撤下；测试数量与证据仅对应当时版本。当前改为四档模式、语义动作与 Rust 后台续租。

首批基础改动已提交并推送 `main`：`b8e57b9`。后续 CI 截图修复为 `cb474d9`、`712d6c8`；第二次修复让 CI 从同一隔离 Xvfb 捕获实际画面，避开 WebKitGTK 静态页面截图等待，功能断言和空图检查继续执行。当前命名场景与 CLI 是基于 `712d6c8` 的未提交工作区，未创建 Tag 或发布。

按维护者选择，CLI 首版通过运行中的桌面执行，不新增独立后台服务。GUI 和 CLI 共用 `AppRuntime`、一个后端锁和配置存储；仅主窗口心跳续租。会话 D-Bus 校验同 UID、拒绝替换既有服务，CLI 不自动激活宿主。请求明确限制 128 KiB 并拒绝未知字段；15 秒等待超时不代表服务端取消，不自动重试硬件操作。

配置升级到 v2，保存曲线草稿和最多 32 个命名场景，整体限制 64 KiB。v1 只读时仅内存迁移，显式保存才写 v2 并备份原文。每次草稿或场景更新在锁内读改写，保留另一类设置；整份导入明确替换草稿及全部场景，仍不自动应用。

场景支持系统档位、OEM 模式或自定义 CPU 功耗，以及风扇曲线组合。OEM 设置绑定厂商/主板/BIOS，执行时重新检查当前权限、双重供电与出厂上限。跨系统服务不能原子切换；执行器每步和最终组合状态读回，失败后逆序补偿，分别报告拒绝、已恢复与恢复失败。已有曲线会先释放再读取真实功耗恢复基线，避免把曲线覆盖值错误当作原状态。

GUI 对保存、删除、预检和执行携带完整原场景，在同一控制锁内比较；CLI 并发替换后的过期操作被拒绝。关闭应用先标记退出，等待当前动作完成再释放控制，排队的新操作不能在释放后重新申请控制。所有能力仍受原有驱动与 BIOS 边界约束。
